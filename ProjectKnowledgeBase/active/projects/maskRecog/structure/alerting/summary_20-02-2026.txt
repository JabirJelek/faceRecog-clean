The code implements the **AlertManager** module as `DurationAwareAlertManager`, with a helper `VoiceInterface` for low‑level alert delivery. Together they handle:

- **Input** – Receives violation data (recognition results) and frame count from the Orchestrator.
- **Business Logic** – Tracks violation duration (`min_violation_frames`), applies batching (`batch_window_seconds`, `min_batch_size`), and generates grammatically correct Indonesian alert messages.
- **Output** – Sends alerts asynchronously via `VoiceInterface` (HTTP GET with retries) to an external server, avoiding pipeline blocking.
- **Configuration** – Accepts parameters through constructor or `update_config()`, as pushed by the Orchestrator.

### Data Flows
1. **Recognition results** → `AlertManager` (from Orchestrator)  
2. **Alerts** → `VoiceInterface` → external HTTP server  
3. **Logging sync hints** – `AlertManager` currently has a `trigger_synchronized_alert` method that coordinates with image logging, indicating a cross‑module dependency that ideally should be managed by the Orchestrator.
